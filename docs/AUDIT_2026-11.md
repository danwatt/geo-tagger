# Codebase audit — November 2026

Principal-engineer pass over backend, frontend, scripts and the uncommitted semantic-search
WIP. Five parallel reviewers, each claim checked by reading code; items marked **✔** were
re-verified independently. Paths relative to `src/geotagger/` unless noted.

Severity: **P0** data loss / security · **P1** wrong results or broken flows · **P2** perf / robustness · **P3** cleanup / QoL.

---

## P0 — data loss & security

1. **✔ Rescan wipes DB-only geotags.** `index.py:585-593` (`upsert_photo` ON CONFLICT overwrites
   `lat/lng/geotag_source`), `index.py:1043` (`is_fresh` returns False when `camera IS NULL`),
   `sidecar.py:119` (`camera = … or None`). With `WRITE_XMP_ON_GEOTAG=0` (default) a hand
   geotag lives only in the DB. Photos with no Make/Model — scans, screenshots, PNGs, many
   videos, i.e. exactly the hand-tagged ones — are "stale" on every boot and re-upserted with
   the file's (empty) GPS. Same for any photo whose mtime changes. Fix: in the UPDATE, keep
   existing coords when `geotag_source='database'` and file has none; store `''` for "no camera".
   Add a regression test.
2. **✔ Deleting a person/family orphans faces.** `index.py:2217-2231`. FKs never enabled, so
   `ON DELETE SET NULL` never fires; faces keep a dead `person_id`, drop out of every queue
   (unlabeled requires `person_id IS NULL`, labeled inner-joins persons). No AUTOINCREMENT, so a
   later new person can **reuse the id and inherit those faces**. Family delete leaves
   `family_id` dangling → `a.name.localeCompare` on null crashes People nav (`web/people.js:566`).
   Fix: explicit `UPDATE … SET person_id=NULL` / `family_id=NULL` in same transaction; one-shot
   repair migration for existing orphans. Also: assign endpoint should 404 on unknown person,
   and `deletePerson` in people.js should drop staged entries targeting it.
3. **✔ ExifTool argument injection → can write originals.** `api/photos.py:412`
   (`previous: list[dict]`, "opaque"), `services/photos_service.py:138`, `sidecar.py:266`.
   `raw_datetime` from client goes into `-XMP:DateTimeOriginal=…`; pyexiftool joins args with
   `\n`, so an embedded newline injects arbitrary ExifTool args (including a target path to an
   original). Fix: typed model, regex-validate `^\d{4}:\d{2}:\d{2} \d{2}:\d{2}:\d{2}$`, validate
   precision enum; reject `\r`/`\n` in every `sidecar.py` arg as defence in depth. Consider keeping
   undo snapshots server-side.
4. **XSS across many innerHTML / Leaflet tooltip sites.** Filenames, EXIF camera, OSM names,
   person names interpolated raw. Examples: `web/app.js:2217-2234` (detail table — the
   `search.js` copy escapes, the app.js copy drifted), `app.js:774, 1488, 2280-2288, 2707`,
   `timesync.js:458, 564-566`, `tag.js:304`, `roadtrip.js:268, 625`, `data.js:707-712`,
   `photo-faces.js:186`, `people.js:1490-1558, 2402-2430`, `custom-places.js:477, 1073`.
   Leaflet `bindTooltip/bindPopup(string)` = innerHTML. Local app, but a crafted EXIF Model
   could call `/api/faces/nuke`. Fix: one shared `escHtml` (see P3 #1) and sweep.
5. **✔ Online geocoder in frontend violates offline constraint.** `web/app.js:2159` calls
   `nominatim.openstreetmap.org`. Also: custom User-Agent header silently dropped by browser
   (breaks Nominatim policy), no `res.ok`. Fix: route through `/api/search/locations` / local data.
   Related: Esri satellite tiles (`custom-places.js:33`, `map.js`, `app.js`) and `picsum.photos`
   in `design-artifacts.html` aren't on the sanctioned list — either update CLAUDE.md or remove.

## P1 — wrong results / broken flows

6. **✔ Semantic search only considers oldest 20k photos** (WIP). `api/search.py:97`
   `limit=20000 if ranked` with `sort=date_asc` feeds `candidate_ids`. Fix: `candidate_ids=None`
   when no filter; otherwise id-only uncapped query, hydrate only top hits.
7. **✔ Newly detected faces never reach unlabeled cache.** `index.py:1382` (`replace_faces`
   doesn't bump generation by design), `faces.py:601` (`drop_from_unlabeled_cache` re-tags stale
   cache to current gen on every label). New-scan faces stay invisible to suggested/clusters/
   untagged search until an unassign/restore or restart; docstring claim is wrong. Fix: separate
   "additions" counter bumped by `replace_faces`; only re-tag if gen unchanged since read. Add a
   module lock (cache mutated from executor threads and loop thread).
8. **✔ Time Sync shifts times by local UTC offset; crashes pre-1970.** `sidecar.py:309, 315`
   `datetime.fromtimestamp()` (local) vs read-back via `calendar.timegm` (UTC). Rescan moves
   every synced photo by the offset (±DST). Negative ts → `OSError` on Windows. Fix:
   `datetime(1970,1,1) + timedelta(seconds=ts)`, as `write_approximate_date` already does.
9. **Pre-1970 dates crash / treated as undated.** `serializers.py:89,101`, `index.py:672,784`
   (`fromtimestamp(ts, tz=utc)` raises on Windows for negative ts) and `photo_datetime <= 0 →
   undated` everywhere. Assigning "~1965" to scans → detail route 500, photo vanishes from
   timeline. Fix: same epoch+timedelta helper; "undated" = `IS NULL` (or a sentinel), not `<= 0`.
10. **Semantic index: model-load failure marks every photo failed forever** (WIP).
    `services/semantic_service.py:39-48` — `_get_visual()` inside per-photo try; generic except
    writes `vec=NULL`, nothing retries NULLs. Fix: load once before loop; add "retry failed".
11. **Embeddings go stale** (WIP) on orientation change (`index.py:928`) or file mtime/size change.
    Fix: delete embedding row in those paths.
12. **Commit-guessed-dates: bad day → partial write, undo impossible.** `api/photos.py`
    validates year/month not day; `datetime(y,2,30)` raises mid-batch, earlier sidecars written,
    500 drops `previous`. Fix: validate full date up front; per-entry try.
13. **"Remove geotag" resurrects embedded GPS on next scan.** `services/geotag_service.py:75`
    — `remove_gps` only touches the sidecar; `read_metadata` falls back to embedded GPS. Also
    stores `str(sc)` (full path) in `sidecar_path` where everything else stores the name, so
    `is_fresh` always mismatches. Fix: pass `sc.name`; persist removal as marker/flag scan respects.
14. **Stale place names after coordinate changes.** `index.py:607-612` (`update_geotag` clears
    city/state/county/country but not `loc_sublocation`/`loc_postal_code`); `upsert_photo`
    changes coords without clearing `loc_*`/`geocoded_at`. Removed-tag photos still match
    "Central Park" text search.
15. **Unwrapped longitudes saved.** `api/geotag.py:16-20` no validation; Leaflet world-copy drop
    sends e.g. `lng=-458`. Fix: `normalize_lng` + `Field(ge=-90, le=90)`.
16. **Antimeridian bbox misses photos.** `geometry.py:42-52` keeps box contiguous (170..190) →
    `BETWEEN 170 AND 190` drops -175. Split into two ranges (hotspots already does).
17. **Hotspot neighbour search misses merges.** `hotspots_service.py:97-101` lon bucket width
    from each point's own lat → neighbours 2+ buckets apart, duplicate hotspots.
18. **Scan never prunes deleted/moved files.** No `DELETE FROM photos` anywhere. Ghost rows keep
    faces/embeddings; moved file gets new id and loses face labels. Fix: post-walk prune of unseen
    rows under scanned roots; match moves by checksum to carry labels.
19. **Datasets installed from Data page unused until restart.** `osm_places.py:49-78`,
    `geocode.py:69-77` latch `unavailable`; only census has `reset()`. `geocode_cache` never
    cleared on dataset change, and its key ignores `GEOCODE_PRECISION` (collisions). Census
    rebuild has Windows unlink race (`data_service.py:384`, `census_builder.py:462`).
20. **Partial downloads treated as complete.** `data_service.py:248-274` streams straight to dest;
    semantic model download (`semantic.py:78-103`) doesn't check Content-Length. Write `.part`,
    `os.replace` on success.
21. **Thumbnail cache writes not atomic** (`thumbnails.py:356,382,411,434,508`) — truncated file
    served forever. **ETag ignores orientation/format** (`api/photos.py:200,228`) — stale rotated
    thumbs after backfill. Fix: tmp+`os.replace`; widen ETag.
22. **Approximate-date tolerance only in one match path.** `faces.py:632-645` vs batch paths
    714-737, 909-935 → photo panel and People queues disagree on suggestions.
23. **`scripts/reembed_faces.py:122-132` duplicates person tags** (snapshots manual faces, then
    IoU-reattaches them to a detected box). Both face scripts write the DB behind a running
    server without bumping caches; reembed snapshot in memory only. Fix: detected-only snapshot,
    JSON journal, refuse/warn if server running.
24. **Rename to existing person name → raw 500** (`persons.name` UNIQUE, `api/faces.py:116`).
    Return 409; and there is no merge-person feature at all — users will hit this.
25. **Work-queue skip list split on commas** (`api/work_queue.py:37`); batch ids contain dir and
    camera names → "Paris, 2019" can never be skipped. Send JSON body.
26. **Stats month chart vs coverage card disagree** (`api/stats.py:117,141` missing
    `come_back = 0`).

## P2 — performance & robustness

35. **Single shared SQLite connection, no lock, no rollback.** `index.py:40`
    `check_same_thread=False`, used by executor + 4 scan threads. A commit in thread B commits
    thread A's half-done `replace_faces`; an exception leaves the txn open for the next commit.
    Fix: `transaction()` context manager with RLock + rollback; or per-thread read connections
    with serialized writes. Biggest structural risk in the backend.
36. **Event-loop blocking in async routes** (CLAUDE.md breach): faces routes
    (`api/faces.py:193,219-229,263-267,432,467,590` — cold cache decodes ~100k embeddings on loop),
    stats routes (`api/stats.py:11,101,180,248,281`), `/api/photos`, by-area/by-bounds/by-location,
    `/api/search/locations` (5 GROUP BYs per keystroke), `/api/geocode/places`. Move to services.
37. **Long admin jobs share the 4-worker request pool** (dataset builds, model downloads, face
    scans with unbounded `limit`). Separate 1-worker admin executor; cap `limit` (`le=500`) on
    `SemanticScanRequest`, `ScanFacesRequest`.
38. **Hung ExifTool freezes the server** — timeout/kill only used by scripts
    (`exiftool_session.py:13,116`); lock held forever.
39. **Startup cost**: camera-less files re-read + SHA-256'd every boot (same root as #1);
    `scanner.py:19` `rglob` walks the whole thumbnail cache; second walk for collisions;
    `is_fresh` N+1; `index.py:477` full R*Tree re-insert each boot.
40. **R*Tree trigger fires on every photo UPDATE** (`index.py:433-441`) — recreate as
    `AFTER UPDATE OF lat, lng`. ~100k needless rebalances per face scan/geocode pass.
41. **Semantic cache check full-scans `photo_embeddings` per query** (`index.py:1326`,
    ~160 MB read); signature changes every batch during indexing → full reload per search. Plan
    §5.4 specified a generation counter — use it. Also fp32 copy of whole matrix per query
    (`semantic.py:259-271`, ~300 MB; ~750 MB peak on reload); keep fp16, upcast per chunk.
    `get_unembedded_photo_ids` returns the full list per batch → O(N²/limit) indexing.
42. **Geocode map: no clustering, every filter change rebuilds every divIcon**
    (`app.js:1958-1984`); `commitPendingGeo` triggers full grid+marker rebuild per point
    (`app.js:2045`). People grid full rebuild per single-face action (`people.js:924-962`, up to
    20k cells); crop cache holds 3000 detached imgs. Batch renders, delegate events, virtualize.
43. **Saved-place search** scans all photos in Python (`index.py:823`) — prefilter via
    `photos_spatial` + `place_bbox`. **ZIP download built in RAM** (`api/photos.py:437`) — spool to
    temp file. **Polygon rings `json.loads` per lookup** (`osm_places.py:129`, `census_places.py`).
44. **Sidecar export is one unbounded request** (`geocode_service.py:28`), rewrites embedded-GPS
    photos too, and `write_gps`/`write_datetime` do 2 extra ExifTool reads just to log. Batch it
    per the client-loop convention; export only `geotag_source='database'`.
45. Misc: `get_photos(ids=)` literal `IN (...)` > 32,766 ids → 500 (use `json_each`); failed
    VACUUM leaves WAL off (`index.py:548`); old rename migration rewrote `faces.photo_id
    REFERENCES "photos_old"` and wasn't atomic (`index.py:157-202`) — blocks ever enabling FKs;
    `find_untagged_face_photos` loads every photo row; per-face queries in `api_photo_faces`;
    `by-area` divide-by-zero at lat ±90; `update_photo_times` no per-item try.
46. **Backup** (`services/backup_service.py`) omits `geocode_ignored` and `date_precision`
    (user-authored), exports all 174k detected faces (regenerable), not a consistent snapshot.
